## 1. 总体架构

```
mapsim (Go, 唯一入口)
 ├─ prep 调度：缓存检查 → 调用 Python → 读取进度 → 加载输出
 ├─ engine：主循环（单一写者）+ 工作池（goroutine 分块并行）
 ├─ store：帧存储（每 5 年一帧格子汇总）+ 检查点（每 200 年一次完整状态）
 └─ api：HTTP 静态页面（embed）+ WebSocket（JSON 控制 / 二进制帧）

prep (Python, conda 环境 mapsim)：地形 → 气候 → 水文 → 资源 → 承载力
web (原生 JS + Canvas2D，嵌入二进制)：参数区 / 地图区 / 时间轴 + 指标曲线
```

## 2. Python 环境（conda）

- 环境定义放在 `prep/environment.yml`（python、numpy、scipy、pillow）。
- Go 按以下顺序查找 Python 解释器：
  1. 配置项 `python_path`（手动指定）
  2. conda 环境 `mapsim`：用 `conda env list --json` 找到环境目录，取 `<env>/bin/python`
  3. 都找不到时：执行 `conda env create -f prep/environment.yml`，把安装输出转发到界面
- **直接执行环境里的解释器，不用 `conda run`。** `conda run` 默认会缓存子进程输出，进度就不能实时显示了。
- Python 脚本用 `go:embed` 嵌进二进制，首次运行时释放到缓存目录；开发模式下直接用源码目录。

## 3. 预处理（Python）

### 3.1 调用协议

```
<python> prep/main.py --map maps/eurasia --out cache/<key>/ --params '<json>'
```

- 缓存键 = hash(图片, map.json, 预处理参数, prep 代码版本)。命中缓存就跳过整个预处理。
- 标准输出每行一条 JSON：`{"stage","progress","message"}`；完成时输出 `{"stage":"done","manifest":"..."}`。
- 错误输出写到标准错误，退出码非零时把错误显示到界面。
- Go 用 `exec.CommandContext` 调用，支持取消。

### 3.2 地图说明文件 `maps/<name>/map.json`

```json
{
  "image": "map.jpg",
  "bounds": {"west": -10, "east": 180, "south": 12, "north": 78},
  "elevation": {"type": "hypsometric", "legend": [["#145a3c", -30], ["#d7da7a", 500], ["#969698", 5000]]},
  "water": {"rule": "blue"},
  "lakes": "lakes.geojson",
  "region_hints": "hints.json"
}
```

当前这张图不是等距投影。D2 期间保留现有的控制点配准代码，作为它专用的"像素→经纬度"适配器；以后换成等距投影的图时，直接用线性变换。

### 3.3 计算流程（方案二：通用规则）

| 阶段 | 内容 | 通用化处理 |
|---|---|---|
| 地形 | 颜色→海拔，水体识别，补湖泊 | 色带和湖泊改由 map.json 提供 |
| 气温 | 纬度基准 − 海拔递减 ± 大陆度振幅 | 去掉经度限制；西伯利亚高压改为"大陆度 × 高纬度"；北大西洋暖流移到区域修正 |
| 降水 | 按季节盛行风做水汽平流，加地形抬升、相对湿度效率、陆面再循环 | 风带只按纬度定义（信风/西风/极地东风，季节南北摆动）；季风改为"大范围陆地占比 × 季节温差"的简单推导，再叠加区域修正 |
| 水文 | Thornthwaite 潜在蒸散，Budyko 实际蒸散，填洼，D8 汇流，干旱区河道损耗 | **待修复**：冻土区径流低估，导致西伯利亚河流几乎断流 |
| 资源 | 旱作、水稻、灌溉、牧草、狩猎采集、渔业、淡水的承载上限（人/km²） | 通用 |
| 承载力 | 各生计方式的人口上限，主导生计，流动性 | 通用 |

区域修正文件 `hints.json`（可选）的格式，示例：`[{"bbox":[100,20,145,50],"field":"monsoon","mul":1.3}]`。

### 3.4 输出：格子数据契约

```
cache/<key>/
 ├─ manifest.json   # 网格参数 + 字段说明
 ├─ cells.bin       # 各字段依次排列，小端字节序，行优先
 └─ preview/*.png   # 各图层预览图（调试用）
```

字段说明的格式：`{id, name, unit, dtype, group, style(continuous|categorical), colormap, range, labels, colors, desc}`。

这份说明同时驱动以下三处，前端不写死任何字段：
- Go 加载时的字段校验
- 前端的图层列表和图例
- 悬浮窗的字段名、单位和说明

## 4. 模拟格属性（0.5°）

| 类别 | 字段 |
|---|---|
| 气候 | 年均温、最冷月/最暖月均温、年降水、夏雨比例、湿润指数、柯本、≥5°C 积温 |
| 资源 | 旱作、水稻、灌溉、牧草、狩猎采集、渔业的承载上限，淡水指数，河流流量 |
| 地形 | 崎岖度（防守加成）、高海拔胁迫 |
| 通行 | 基础迁移阻力，按生计方式（农耕/游牧/狩猎/渔猎）给阻力倍率，海峡可跨越标记 |
| 动态（Go） | 气候波动系数、已掌握的技术、人口、家族数、政权前三名影响力 |

经纬格的面积随纬度变化：承载上限要按格子面积换算，移动距离按实际 dx、dy 计算。

## 5. Go 模拟引擎

### 5.1 数据布局
- 家族数据按字段分别存成数组：`Size, Store []float32; Cell, Parent, Root []int32; UID []int64; Traits [K][]float32; Grudge [4]{Target int32, Value float32}`。
- 不用 `[]*Family`。数组预先分配，每步复用。
- 每个家族有一个永不复用的唯一 ID。数组压缩时同步重映射 `Parent`。

### 5.2 每步的阶段（1 步 = 1 年）
1. 气候波动（每 10 年生成一次低分辨率噪声，放大到全图）
2. 生产与竞争：按格子汇总劳力，产出随劳力递减
3. 消耗、死亡、繁衍、分家（属性继承 + 变异）
4. 文化传播：向本格属性均值靠拢
5. 迁移：在周围 9 格中按"吸引力 − 阻力"打分
6. 叛乱：本地实力大于上级在此地的投送力量时独立
7. 征服：并行提出目标 → 按 (目标ID, 进攻者ID) 排序后串行裁决
8. 重算最高首领（每轮跳到上级的上级）+ 环检测断言
9. 每 5 年：政权影响力场（带虚拟总源点的多源最短路，限制最大距离）、政权间战争、继承危机

### 5.3 并行
- 工作池大小等于核数，按下标分块。每个线程有自己的累加缓冲，最后合并。
- 随机数：每块数据由 `PCG(seed, year, chunk)` 派生，保证同样参数得到同样结果。
- 只有主协程修改模拟状态；控制命令经通道在两步之间处理。

### 5.4 仇恨
- 家族层：每个家族 4 个槽位（政权ID, 值），每年 ×0.97 衰减，新仇替换最弱的一条。
- 政权层：稀疏表 `map[[2]int32]float32`，同样衰减。政权消亡后相关条目过期。

## 6. 通信协议

**控制消息（JSON，双向）**

| 前端 → 后端 | 后端 → 前端 |
|---|---|
| `start` `pause` `step` `setSpeed` `seek{year}` `setParams{...}` `subscribe{layers:[...]}` `inspectCell{cell}` | `paramSchema` `prepProgress` `status{year,running,computedUntil}` `cellDetail{...}` `error` |

**帧（二进制）**：`[头部: 版本, 年份, 字段数] + 每个字段 {id:u16, dtype:u8, data}`，只包含已订阅的动态图层。
- 静态字段在连接时一次性下发。
- 前端处理不过来时，后端只保留最新一帧。

## 7. 前端

- **地图**：WebGL2，每个字段一张纹理，每种渲染方式一个着色器（连续/分类/双变量/线/点）；边界线在着色器里比较相邻格子的编号得出。
- **图层组**：基础 · 气候 · 资源 · 人口 · 社会 · 政治 · 综合。同一时间只允许一个填色图层，其余只能是线、点或明暗调制。
- **综合预设**：政治综合（填色 + 人口明暗 + 边界 + 首府）、资源×人口（双变量）、生计 + 政治边界。
- **悬浮窗**：顶部固定显示位置、柯本、地形和阻力；与当前图层对应的一节展开，其余节各一行。静态和动态汇总数据前端已有，0 延迟；家族明细在悬停约 150 ms 后向后端请求，并缓存。
- **详情面板（点击固定）**：资源对比、家族列表（属性雷达图 + 本格平均值参照）、统治链、政治与仇恨、该格的历史小图。悬停时联动高亮政权领土和下级区域。
- **时间轴**：区分已计算和未计算区间。拖到已计算区间读帧存储；从某年改参数重跑时，读最近的检查点。
- **指标曲线**：总人口、政权数、最大政权占比、边界平均存活年数。

## 7.5 回放存储

### 格子帧（每 5 年一帧）

| 字段 | 类型 | 字节 |
|---|---|---|
| 人口（对数量化） | u16 | 2 |
| 家族数 | u16 | 2 |
| 主导生计 | u8 | 1 |
| 第4层：多数家族所属的最高首领（本帧政权表下标） | u16 | 2 |
| 第5层：政权第一名（下标） | u16 | 2 |
| 第5层：政权第二名（下标，用于重叠） | u16 | 2 |
| 第一名影响力占比 | u8 | 1 |
| 平均统治层级深度 | u8 | 1 |
| 家族平均属性 × 6 | u8 × 6 | 6 |
| 仇恨热度 | u8 | 1 |
| 气候波动 | u8 | 1 |

- 每格约 21 字节，单帧原始约 600 KB，再加本帧政权表（下标 → 全局政权ID、人口、面积、首府），约 64 KB。
- 每 100 年（20 帧）一个关键帧，中间帧对上一帧做逐字段差分（分类字段按 XOR，连续字段按差值），然后用 zstd 压缩。
- 800 帧，预计压缩后 65–130 MB。帧索引常驻内存，压缩帧可以放内存也可以按需读盘。

### 检查点（每 200 年一个）

- 内容：家族数组全部字段（约 92 字节/家族）、政权状态、仇恨稀疏表、格子动态状态、随机数状态。
- 10 万家族时约 10 MB，压缩后约 6–8 MB；共 20 个，约 120–160 MB。
- 模拟可复现，所以查看历史上某年的家族明细 = 读最近的检查点 + 往后重算，不超过 199 年。

### 其他

- 政权历史总表：所有出现过的政权（ID、名字、颜色、首府、存续年份、峰值规模），约 3–13 MB。
- 指标曲线：每年一行，约 160 KB。
- 政权层事件日志：征服、吞并、叛乱、继承，约 1–13 MB。家族层的征服不逐条存，只计入汇总量。

### 预计总量

约 200–300 MB（10 万家族上限时）。

### 目录

```
runs/<run_id>/
 ├─ run.json            # 参数、种子、manifest 引用、已计算年份
 ├─ frames.bin          # 压缩帧，依次追加
 ├─ frames.idx          # 每帧的 (年份, 偏移, 长度, 是否关键帧)
 ├─ polities.bin        # 政权历史总表

```

## 10. 风险

- 方案二的气候精度低于现在手调的欧亚版本，预计气温误差 4–5°C。
- 是否能出现"多国并存"取决于参数平衡，需要指标加参数扫描来调。
- 只要有一处冲突按到达顺序裁决，结果就会依赖线程调度，不可复现。所有裁决必须按确定的键排序。

## 11. 实现记录（与设计的差异）

| 项 | 设计 | 实际 | 原因 |
|---|---|---|---|
| Python 脚本 | go:embed 进二进制 | 直接使用仓库里的 `prep/` | 开发期更方便；`findRoot` 自动定位仓库根目录 |
| 包结构 | agents / polity / engine 分包 | 合并为 `sim` 一个包，引擎在 `api/engine.go` | 第 3–5 层共享家族数组，分包只会增加导出面 |
| 帧格子 | 全部格子 | **只存陆地格**(顺序 = World.LandIdx) | 体积减少 42% |
| 帧政权表 | 所有引用到的政权 | 家族数 < 3 的政权记为"零散小族"(65535) | 每帧政权表从约 4000 条降到约 1000 条 |
| 慢变字段 | 每帧 | 6 项属性均值与仇恨热度每 25 年刷新一次 | 中间帧差分为 0，几乎不占空间 |
| 运行中改参数 | 支持并在时间轴标记 | 参数在一次演化内固定；改参数 = 开新演化 | 保证"检查点 + 重算"与原始历史逐位一致 |
| 影响力场 | 多源最短路 | 多源最短路 + 2 轮多数平滑(≥5/8 邻格同属则并入) | 消除斑点状飞地，飞地上的家族随后会倒戈 |
| 查看历史家族 | 读检查点 + 重算 | 同上，并在暂停时后台预热 | 首次点击最长约 18 秒，预热后立即显示 |

已知局限：
- 东西伯利亚降水偏少(雅库茨克模拟约 90mm，实测 240mm)，叶尼塞、勒拿、科雷马的流量偏低。
- 南亚/东亚季风、北大西洋暖流来自 `hints.json` 区域修正，不是从地理推导出来的。
- 原图不是等距投影，用 46 个控制点的三次多项式配准，平均误差约 70km。

实测规模(10 万家族上限)：每年约 95ms(8 核)；4000 年回放约 150MB 帧 + 约 140MB 检查点。

## 12. 随机超级帝国（第 5 层扩展）

模拟历史上突然崛起、疆域极其辽阔的大帝国（如蒙古帝国）。实现见 `server/sim/super.go`。

| 阶段 | 规则 |
|---|---|
| 崛起 | 每 5 年以 `superRate`（默认 0.012，约 400 年一次）概率触发。从 ≥20 个家族的政权中加权抽取，权重 = 规模 ×(0.3+好战)×(0.3+2×放牧×流动)，偏好游牧政权 |
| 鼎盛 | 持续 80–200 年。实力 ×`superPower`(默认 3)，投送距离 ×`superReach`(默认 3)，最远距离上限放宽到 min(0.2×3, 0.6) 个地图宽度；每 5 年可同时打 3 场战争，开战概率 ×2；内部叛乱概率 ×0.3 |
| 饱和 | 实力加成随统治人口占比线性消退，占比达 `superCap`(默认 35%) 时加成为 0：疆域可以横跨稀疏的草原，但不会吞掉整个大陆 |
| 衰落 | 期满(或首领被吞并)时加成消失，强制继承危机：被吞并的旧政权 90% 复国，本族分支按忠诚度分裂 |

界面：鼎盛期政权名前加 ★，标为"大帝国/大汗国"；事件栏显示崛起与瓦解。实测：最大政权占比在崛起期升到 35–50%，瓦解后回落到 15–25%，政权数始终维持在 300 个左右。

## 13. MVP：可编程的世界推演引擎(已实现)

定位：可复现、可编程的世界推演引擎。用户带来地形(高程图或草图)，引擎推演出气候、资源、人口、政权历史与交通，以标准数据格式交付。首要客户：策略/沙盒类游戏团队；其次是职业作者与 IP 团队。

| 模块 | 实现 | 位置 |
|---|---|---|
| 导入 | 灰度/数值高程(8/16 位 PNG、TIFF、浮点 GeoTIFF，GeoTIFF 自动读取范围)；规则版草图(颜色→海/河/山/高地/平原 → 合成高程)；分层设色 | `prep/mapprep/terrain.py`、`config.py` |

已验证：南半球合成大陆、草图、半球对称性(Python)；约束锁定与检查点重算一致性、GeoTIFF/多边形、租户密钥与额度(Go)；上传→预处理→带约束演化→全格式导出→复用→接口→回调签名→权限与额度的端到端冒烟测试。

MVP 已知局限：
- 草图只做规则识别(按颜色)，没有 AI 理解；分层设色需要用户提供色带。
- 气候通用模式(无区域修正)对欧亚的校验：气温误差约 4.2°C，降水对数误差 0.73。
- 持久化是 JSON 文件，适合单机与试点；规模化需要换数据库与对象存储。
- 回调默认禁止内网地址；任务并发数由 `-workers` 控制，单机运行。
- Docker 镜像未在本机实际构建(当前用户无 Docker 权限)。

## 15. 色带自动识别

用户上传自定义分层设色图(JPG/PNG)时，自动得到"颜色 → 海拔"色带。代码在 `prep/colorband/`，由 `POST /v1/colorbands` 调用，并在 AI 识图识别出分层设色图后自动运行。该目录不计入预处理缓存键。

**第 1 步：聚类 + 拓扑排序(兜底)**
- 预处理：
  - 缩到约 120 万像素(BOX)，再做 3×3 中值滤波。
  - 主要颜色不超过 64 种且覆盖 97% 像素时，按"精确色"处理(调色板 PNG、无抗锯齿)。
  - 去掉四周纯色边框；排除图例区域。
- 特征：`[0.35·L*, 300·r/(r+g+b), 300·g/(r+g+b)]`。晕渲近似把 RGB 乘一个系数，色度不变，所以亮度降权。
- 聚类：k-means(28 类)后合并近邻中心，面积不足 0.2% 的类并入最近的类。
- 剔除：
  - 核心比例(腐蚀后剩余)低的类视为线条、文字或过渡色，剔除后按最近的有效类回填。
  - 平涂图在第二轮用更严的标准剔除 JPG 色度抽样产生的过渡带。连续色带每一段都落在相邻两段之间，不做这一轮。
- 排序：
  - 统计类间边界长度，归一化为 `W_ij/√(P_i·P_j)`。
  - 求边权最大的哈密顿路径：≤12 类时状压 DP 精确求解，否则用多起点贪心 + 2-opt。
  - 链上相邻且色度相同的两类是同一层被晕渲拆开，合并后重排。
- 水体：蓝色规则(与预处理一致)；另外，占据地图外缘 40% 以上、面积 10% 以上的浅色(白、浅灰、浅青)视为非蓝色的海，输出到 `water`，上传时作为 `elevation.water` 提交(预处理按"离水体颜色比离任何色带颜色更近"判为水；透明像素也算水)。
- 方向：贴海的一端为低；找到图例时以图例排列为准(蓝色所在一端为低；没有蓝色时竖排下低上高、横排左低右高)，图例覆盖全部陆地颜色时直接按图例排序；都没有时按配色习惯判断(绿低、灰白高)。
- 精确色图(调色板 PNG、无抗锯齿)：颜色只合并 RGB 几乎相同的；不做晕渲合并和过渡色剔除；图例色与地图色须完全一致才配对。
- 数值：按层数选常见分级模板(如 8 层：0/100/200/500/1000/1500/2000/3000 m)。

**第 2 步：参考 DEM**
- 数据：ETOPO1 抽稀到 5′，`data/refdem/etopo.npz`，用 `fetch_refdem.py` 生成。
- 配准：地图海陆掩膜与参考海陆的 IoU，先粗搜平移 ±8%，再做平移 + 缩放的模式搜索。IoU 提高 1% 以上才采用微调后的范围，低于 35% 时放弃校准。
- 阈值：相邻两层交界像素处参考高程的中位数，即等高线高程；交界线不足 20 像素时用两层中位数的中点。阈值做加权保序回归后，贴近整百、整千时取整。
- 层值：取上下阈值的中点，最高层取参考中位数。参考高程判断方向相反时以参考为准。

**第 3 步：图例**
- 定位：
  - 找均匀像素(5×5 标准差 < 7)、且被颜色突变切开的连通块，筛选近似矩形的块。
  - 按左对齐、等宽(竖排)或上对齐、等高(横排)分组，按间距切段，取成员最多、相邻颜色不同、跨度足够的一组。
- 配对：色块颜色对应到最近的地图类(颜色改用不带晕渲的图例纯色)。AI 读出的刻度按位置换算为色块序号(可为小数)，插值到每个色块中心：刻度标在交界处时得到区间中点，标在中间时得到该值。
- 渐变图例(没有色块)：在刻度位置取色，对应到最近的地图类。

**融合**：数值来源依次为图例读数、参考高程、插值、模板，最后沿高低顺序做保序平滑。每层置信度 = 来源基础分 × 该层邻接关系落在链上的比例。图例读数与参考高程差异过大、图例排列与拓扑顺序不一致时给出警告。

**回归测试**(`prep/colorband/test_colorband.py`)：
- 合成图带晕渲、JPG、经纬网、文字、河流和图例：
  - 拓扑排序：8/8 层顺序正确。
  - 图例刻度：误差 ≤ 6 m。
  - 参考 DEM：偏差 1° 的范围微调回 0.1° 以内，阈值与真值一致。
  - 三步合用、精确色 PNG、浏览器 JPG 过渡带也都覆盖。
- 欧亚图(连续色带 + 重晕渲)：排序与已知色带的秩相关 0.988。

**局限**：
- 非蓝色的海只在占据地图外缘时自动识别；内陆的非蓝色湖泊若与海不同色，需要手工加入水体颜色。
- 灰色系的高山层只有明暗差异，会和晕渲一起被合并。
- 参考 DEM 只适用于真实地理区域；虚构世界只能用图例或模板。

## 16. 气候模型修订(2026-10-19)

起因：自定义大陆(10-75°E/N)上亚寒带针叶林到 32°N、西岸没有地中海气候、36.6°N 2100 m 处出现苔原。核对欧亚 62 站发现同样的问题：多雨站点七月偏冷 5-15°C(卑尔根 0°C、雅典 13.8°C、曼谷 20.6°C)，地中海带夏季降水是实测的 5-30 倍，所有 Csa 站点都没识别出来。

| 改动 | 原因 |
|---|---|
| 夏季增温/降温按**夏半年降水**计算，湿润一侧最多 -2.5°C(原为按年降水、最多 -6.7°C) | 纬向基准气温已含典型云量；地中海式气候年降水不少但夏季晴空 |
| 新增**副热带高压夏季下沉**：纬度 37°±9°、沿纬圈向西到大洋的距离(衰减 2500 km)，排除大陆东侧(大尺度陆地在西边) | 原模型夏季 30-45° 只有很弱的动力抑制，而且陆面再循环率固定 0.8，水汽在内陆永不耗尽 |
| 下沉区夏季：动力因子 -0.6·S，再循环与地形雨 ×(1-0.7·S) | 副高下蒸散的水汽不在本地成雨 |
| 通用季风：海在西侧(大陆西岸)不吹向陆的夏季风；副高区季风 ×(1-S) | 季风只出现在大陆东侧、南侧 |
| 气温递减率 5.5 → **4.5 °C/km**(作用于平滑地形) | 宽阔高原有地面加热：埃利、托诺帕、安卡拉、喀布尔、拉萨的有效递减率 3.2-4.3 |

欧亚验证(有区域修正)：

| 指标 | 修订前 | 修订后 |
|---|---|---|
| 气温 MAE / 偏差 | 3.63 / -1.08 | 2.95 / -0.22 |
| 降水对数比 MAE | 0.51 | 0.48 |
| 柯本前两位命中 | 36/62 | 42/62 |

无区域修正时，柯本前两位从 27/62 提高到 32/62。罗马、伊斯坦布尔为 Csa，马德里、雅典为 Csb：都已是夏干，但夏季仍偏凉 3-10°C，降水偏多约一倍。

自定义大陆上的结果：
- 西岸 35-41°N 为 Csa/Csb。
- 36.57°N 26.38E(2100 m)为 Csb，温带森林：最暖月 16°C，最冷月 0°C，冬雨。
- 32-38°N 的 Dfc 只出现在平滑海拔 2800-3400 m 以上，属于亚高山针叶林。
- 苔原在 50°N 以南只见于 2000 m 以上的山地。

已知不足：
- 塔什干、德黑兰仍偏湿偏冷。中亚内陆的冬季水汽来源过多。
- 卑尔根格点落在峡湾山地，平滑后的海拔偏高。
